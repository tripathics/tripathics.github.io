10:T2e44,<h2 id="introduction">Introduction<a href="#introduction" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p>NodeJS is a runtime environment to execute JavaScript code outside the web browser.</p>
<p>Continuing with the earlier discussion, after successfully installing node and npm, I went on to install "http-server" from <code>npm</code> globally only to get this <code>EACCESS</code> error.</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">npm</span> <span class="token parameter variable">-g</span> <span class="token function">install</span> http-server
</span><span class="code-line">
</span></code></pre>
<p>In this blog, first I'll install Node and npm system wide. Then I'll tell <code>npm</code> where to install global packages. Next, I will install <code>n</code> to manage multiple versions of node.</p>
<h2 id="installing-node-and-npm-globally">Installing Node and npm globally<a href="#installing-node-and-npm-globally" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p>First update the local package list to see if there's any update available using <code>apt-get</code></p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">sudo</span> <span class="token function">apt-get</span> update
</span></code></pre>
<p>Then install <code>nodejs</code> and <code>npm</code> packages</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">sudo</span> <span class="token function">apt-get</span> <span class="token function">install</span> nodejs <span class="token function">npm</span>
</span></code></pre>
<p>To verify the install, check their versions</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">node</span> <span class="token parameter variable">-v</span>
</span><span class="code-line">v18.7.0
</span></code></pre>
<h2 id="configuring-global-install-paths-for-npm">Configuring global install paths for npm<a href="#configuring-global-install-paths-for-npm" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<p><code>npm</code> uses the <code>prefix</code> option to set its global install path. I can set this to a directory inside my home. Being inside my home directory, this gets rid of that <code>EACCESS</code> error when installing global packages as I have read/write access to a directory inside my home folder.</p>
<p>First I will <code>cd</code> into my home directory</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token builtin class-name">cd</span> ~
</span></code></pre>
<p>Then create a folder named "global-node-modules"</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">mkdir</span> global-node-modules
</span></code></pre>
<p>Now to install any global package to this directory, we can use that <code>prefix</code> option like so</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">npm</span> <span class="token parameter variable">--prefix</span><span class="token operator">=</span><span class="token environment constant">$HOME</span>/.global-node-modules <span class="token function">install</span> <span class="token parameter variable">-g</span> http-server
</span></code></pre>
<p>I can specify this option as default in <code>.npmrc</code> file in my home directory so that I don't need to specify it every time I'm doing <code>npm install -g</code>. My <code>.npmrc</code> file looks like this.</p>
<pre class="language-bash"><code class="language-bash code-highlight"><span class="code-line"><span class="token assign-left variable">prefix</span><span class="token operator">=</span>/home/shyam/.global-node-modules
</span></code></pre>
<p>Now that the prefix is set, I need to include the modules to my <code>PATH</code> so that I can run the globally installed modules from anywhere. For this, add</p>
<pre class="language-bash"><code class="language-bash code-highlight"><span class="code-line"><span class="token builtin class-name">export</span> <span class="token assign-left variable"><span class="token environment constant">PATH</span></span><span class="token operator">=</span><span class="token string">"<span class="token environment constant">$HOME</span>/.global-node-modules/bin:<span class="token environment constant">$PATH</span>"</span>
</span></code></pre>
<p>to the end of your <code>.bashrc</code>, <code>.zshrc</code> or equivalent file. After all, the modules will be located inside the <code>.global-node-modules/bin</code> folder.</p>
<h2 id="n---managing-node-versions">`n` - Managing node versions<a href="#n---managing-node-versions" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h2>
<h3 id="installing-n">Installing `n`<a href="#installing-n" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h3>
<p>Now that <code>npm</code> is available after installing node and npm in the first step, I can install <code>n</code> <em>globally</em> using <code>npm</code>.</p>
<pre class="language-shell"><code class="language-shell code-highlight"><span class="code-line"><span class="token function">npm</span> <span class="token function">install</span> <span class="token parameter variable">-g</span> n
</span></code></pre>
<p><code>n</code> also like <code>npm</code> tries to install packages to <code>/usr/local</code> by default. This behaviour can be changed by updating the <code>N_PREFIX</code> to a folder inside the home directory.<br>
I can set it to a directory inside home like <code>.n</code> using <code>export N_PREFIX=$HOME/.n</code>. This line also need to be added to the <code>.bashrc</code> or similar configuration file for your shell.</p>
<p>After doing this, I must also add the <code>N_PREFIX/bin</code> folder to <code>PATH</code> to be able to execute the current version of node selected using <code>n</code>.</p>
<p>Thus if you are using bash, the following lines need to be added to <code>.bashrc</code> file</p>
<pre class="language-bash"><code class="language-bash code-highlight"><span class="code-line"><span class="token punctuation">..</span>.
</span><span class="code-line"><span class="token builtin class-name">export</span> <span class="token assign-left variable">N_PREFIX</span><span class="token operator">=</span><span class="token string">"<span class="token environment constant">$HOME</span>/.n"</span>
</span><span class="code-line"><span class="token builtin class-name">export</span> <span class="token assign-left variable"><span class="token environment constant">PATH</span></span><span class="token operator">=</span><span class="token string">"<span class="token environment constant">$PATH</span>:<span class="token variable">$N_PREFIX</span>/bin"</span>
</span></code></pre>
<h3 id="using-n">Using `n`<a href="#using-n" aria-hidden="true" tabindex="-1" class="heading-link"><svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="1em" height="1em" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></a></h3>
